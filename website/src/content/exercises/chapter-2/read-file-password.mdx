上一个练习里，我们捕获了**所有** `read()` 调用。但如果我们只关心某个特定文件的读取，比如 `/tmp/password` 呢？

问题在于：`read()` 操作的是文件描述符，不是文件名。当进程调用 `open("/tmp/password")` 时，内核返回一个文件描述符（fd）——一个进程内唯一的数字（比如 `4`）。后续的 read 调用就用这个数字：`read(4, buf, ...)`。

等我们看到 `read()` 系统调用时，手里只有 `fd`，文件名早就没了。

要按文件名过滤读取，我们需要把 `open()` 和 `read()` 两个系统调用关联起来：在 open 时记下哪个 fd 对应 `/tmp/password`，拦截 read 时再用上这条信息。

## 关联 open 与 read

我们需要挂载四个事件，并在它们之间传递信息：

当进程打开 `/tmp/password` 时：
1. **open entry** - 我们能拿到路径名，并检查它是否匹配目标
2. **open exit** - 我们拿到分配给这个文件的 fd

当同一个进程从这个 fd 读取时：

3. **read entry** - 我们看到读的是哪个 fd，以及目标缓冲区
4. **read exit** - 我们看到写入了多少字节

难点在于把这些点连起来：在第 3 步时，我们怎么知道 fd `4` 就是第 1 步里关心的那个？

## 用三个 map 跟踪

我们用三个 map 在这条流水线里传递信息。

**open 期间的临时标记：**

在 open entry 处，我们把正在打开 `/tmp/password` 的 PID 记到 `open_curr_fd_interesting` 里。到 exit 时再查这个标记，就知道返回的 fd 是不是我们关心的。

用 PID 作 key 是安全的，因为系统调用期间线程被阻塞了——在这次调用完成之前它没法再发起另一个 `open()`。

**对关心的 fd 做持久跟踪：**

一旦知道 PID `123` 那边 fd `4` 对应的是 `/tmp/password`，我们就要记住这个对应关系。之后看到 `read(4, ...)` 时，就能检查 `(123, 4)` 是否在我们的 map 里。

这需要用到我们的第一个复合 key：

```c
struct pid_fd_key {
    u64 pid;
    u32 fd;
};

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 1024);
    __type(key, struct pid_fd_key);
    __type(value, u8);   // marker
} open_interesting_fds SEC(".maps");
```

key 里 PID 和 FD 都要有，因为一个进程可以同时打开多个文件描述符。fd `4` 可能是 `/tmp/password`，而 fd `5` 是 `/etc/config`。

**read 期间的临时存储：**

和上一个练习一样，我们定义 `read_curr_fd_buf`，把缓冲区指针从 read entry 保存到 read exit，用 PID 作 key。
