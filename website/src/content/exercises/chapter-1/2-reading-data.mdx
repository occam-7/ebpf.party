在上一个练习里，我们用了一个辅助函数来问「谁在运行？」。

现在，让我们通过查询挂载点能拿到的数据，来回答关于正在运行的进程的问题。

对于 `sched_process_exec`，内核会提供一个包含特定事件数据的结构体，例如进程 ID（PID）和文件名。

在任意 Linux 机器上执行下面的命令，就能看到内核提供的上下文格式：
```bash
$ cat /sys/kernel/tracing/events/sched/sched_process_exec/format
format:
  unsigned short common_type;           offset:0;   size:2;
  unsigned char common_flags;           offset:2;   size:1;
  unsigned char common_preempt_count;   offset:3;   size:1;
  int common_pid;                       offset:4;   size:4;
  __data_loc char[] filename;           offset:8;   size:4;
  pid_t pid;                            offset:12;  size:4;
  pid_t old_pid;                        offset:16;  size:4;
```

或者，在编辑器里 <kbd>Ctrl</kbd>+<kbd>Click</kbd> 点一下 `trace_event_raw_sched_process_exec` 就能看到它的定义。

## 挑战
直接从事件数据里提取被执行程序的 **PID** 和 **filename**。

获取 PID 在这里很简单，直接读就行：
```c
int pid = ctx->pid;
DEBUG_NUM("PID", pid);
```

但读取文件名就麻烦一些。看看上面的类型声明，
它是 `__data_loc char[]`。

这不是一个普通的指针；`__data_loc` 前缀表示该字段只包含字符串的**编码位置**，而不是字符串本身。

本质上，filename 字段里装的是一个 32 位整数，打包了两部分信息：

  - 低 16 位：偏移量（字符串距离结构体起始位置多远）
  - 高 16 位：长度（字符串有多长）

要拿到真正的字符串，我们需要解码它的位置：

  1. 读取 `__data_loc_filename` 字段
  2. 掩掉低 16 位（`val & 0xFFFF`）得到偏移量
  3. 右移取出高位（`val >> 16`）得到长度
  4. 把这个偏移量加到 `ctx` 指针上

不过，我们没法直接从算出来的地址读取数据：

```c
char* fname = (void *)ctx + off;
DEBUG_STR("Filename", fname);
```

为什么不行？

正如我们在入门部分看到的，eBPF 程序运行在沙箱中。像 `ctx + off` 这样算出来的地址指向的是内核内存（不是程序的栈）。

当我们用一个非本地地址调用 `DEBUG_STR` 时，内核辅助函数会拒绝从那段内存读取，于是「DEBUG」的内存就保持未初始化状态。

不过你可以试一试！它不会让内核崩溃，而是会返回类似这样的东西：`�����`。

要解决这个问题，我们需要用 [bpf_probe_read_kernel_str](https://docs.ebpf.io/linux/helper-function/bpf_probe_read_kernel_str/) 辅助函数把数据复制到「本地内存」（栈）里。

```c
char fname[32];
bpf_probe_read_kernel_str(fname, sizeof(fname), (void *)ctx + off);
```

这样之后，`fname` 缓冲区就被填好了，我们可以对它调用 `DEBUG_STR`。
