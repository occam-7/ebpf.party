上一个练习里，我们用 kprobe 跟踪了 TCP 连接的建立完成。现在我们来在 HTTP 数据发送时拦截它。

我们**本可以**挂到 `sendto()` 系统调用上，但它同时也会拦截 [vsock](https://gitlab.com/vsock/vsock) 传输，其中还包括 `DEBUG_*` 调用，用起来相当别扭。

而且，那也完全不符合 `kprobe` 这一章的主题！

所以我们换个思路，挂到 `tcp_sendmsg()` 上 —— 它只在 TCP 流量上被调用。


## 从 tcp_sendmsg 读取数据

我们可以找到 `tcp_sendmsg` 的签名，它位于 `net/ipv4/tcp.c`，即：

```c
int tcp_sendmsg(struct sock *sk, struct msghdr *msg, size_t size);
```

我们可以通过 `msg` 参数拿到用户态缓冲区，不过稍微有点绕。

`struct msghdr` 的简化定义：

```c
struct msghdr {
    struct iov_iter msg_iter;  // Iterator containing buffer info
    // ...
};

struct iov_iter {
    union {
        struct iovec __ubuf_iovec;  // Userspace buffer base/len
        // ...
    };
};

struct iovec {
    void *iov_base;
    u64   iov_len;
};
```

所以我们要读取的用户态缓冲区，其地址存放在 `msg->msg_iter->__ubuf_iovec.iov_base`。

记住不能直接解引用指针，所以你得手动一层一层地读下去。注意每一层指针分别属于哪个地址空间。


## HTTP 请求的结构

HTTP 请求是文本格式的：

```text
POST /api/data HTTP/1.1
Host: example.com
Authorization: Bearer secret_token_here
Content-Type: application/json
```

各 header 之间用 `\r\n`（CRLF）分隔。每个 header 形如 `Name: Value`。

以前，在 eBPF 里操作任何基于字符串的协议都**极其**繁琐。算你走运，自 [2025 年 6 月](https://lore.kernel.org/all/4b008a6212852c1b056a413f86e3efddac73551c.1750917800.git.vmalik@redhat.com/) 起，我们可以直接做一些字符串操作了。

这个练习里我们会用到两个函数：

- `bpf_strstr(char *haystack, char *needle)`：查找子串，返回下标，出错时返回负数
- `bpf_strchr(char* str, char c)`：查找字符，返回下标，出错时返回负数

例如，
```c
int auth_pos = bpf_strstr(buf, "Authorization: Bearer ");
```
如果找到了，`auth_pos` 里就是 needle 所在的位置。

稍微算一下，你就能确定 token 应该从哪里开始，然后从那读到行尾（以 `\r` 标记）。

要走到行尾，可以用
```c
int token_pos = bpf_strchr(&buf[token_start], '\r');
```
它会给出**第一个** `\r` 的位置，从 `token_ptr` 开始数。
